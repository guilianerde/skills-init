# diff 采集：上线方案的映射与抽取规则

基线、分层过滤命令、排除与巨量兜底、通用抽取规则见 `references/diff-collection-common.md`。本文件只写上线方案特有的部分。

## 层 → 事实类别

上线方案的章节由项目模板决定（见 SKILL.md Step 3）。采集时按下表归类事实，填充时放进模板里**含义对应**的章节；模板里没有对应章节的事实不擅自加章节，在交付摘要里列出。

| 层 | 用途 | 事实类别 |
|---|---|---|
| 接口入口 | 接口验证 | 上线后验证 |
| 业务逻辑 | 业务影响 | 上线服务 / 改动范围 |
| SQL 脚本 | DDL | 中间件上线：DB |
| 配置 | 配置中心 / 开关 | 中间件上线：配置 |
| 构建文件 | 依赖 | 中间件上线：依赖 |
| 定时任务 | 定时任务 | 监控 |
| 消息 | topic 监控 | 监控 |

数据结构层（entity / dto / vo）只在需要确认 DDL 时补读。

## 复用技术方案（--tech）

传入 `--tech <path>` 时先解析该技术方案：接口、涉及服务、DB 变更、表名这几类章节（按章节含义找，不按编号）→ `tech_context`。对应层直接复用 `tech_context`，跳过该层 diff 采集；技术方案里标「待补充」的项仍按 diff 采集。

## 特有抽取规则

- **接口**：路径 + 方法，用于生成上线后验证用例。
- **改动范围**：受影响的模块 / 包名汇总。
- **DDL 表名**：进数据评审类章节（模板有、且 `profile.data_review` 为 true 时）。
