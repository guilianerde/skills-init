# diff 采集：上线方案的映射与抽取规则

基线、分层过滤命令、排除与巨量兜底、通用抽取规则见 `references/diff-collection-common.md`。本文件只写上线方案特有的部分。

## 层 → 上线方案模块

| 层 | 用途 | 喂给模块 |
|---|---|---|
| 接口入口 | 接口验证 | 四 上线后技术验证 |
| 业务逻辑 | 业务影响 | 一 改动范围 |
| SQL 脚本 | DDL | 二 中间件上线 |
| 配置 | 配置中心 / 开关 | 二 |
| 构建文件 | 依赖 | 二 |
| 定时任务 | 定时任务 | 五 监控方案 |
| 消息 | topic 监控 | 五 |

数据结构层（entity / dto / vo）只在需要确认 DDL 时补读。

## 复用技术方案（--tech）

传入 `--tech <path>` 时先解析该技术方案：模块 4 接口表、模块 5 服务表、模块 6 DDL、模块 7 表名 → `tech_context`。对应层直接复用 `tech_context`，跳过该层 diff 采集；技术方案里标「待补充」的项仍按 diff 采集。

## 特有抽取规则

- **接口**：路径 + 方法，用于生成上线后验证用例。
- **改动范围**：受影响的模块 / 包名汇总。
- **DDL 表名**：进 2.3（`profile.data_review` 为 true 时）。
